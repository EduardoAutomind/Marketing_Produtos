Como funciona (3 mecanismos)

Tudo em Settings → Security & Privacy, em dois níveis: organização (os 8 projetos) e projeto.

Precedência: config de Data Scrubbing na organização sobrepõe a do projeto — para usar o nível de projeto nesses toggles, desligue o da org antes. Já as regras de Advanced Data Scrubbing coexistem, e regra avançada tem precedência até sobre Safe Fields.

1) Data Scrubber padrão (já vem ligado)

Redige cartões de crédito e valores/chaves com: password, secret, passwd, api_key, apikey, auth, credentials, token, bearer, private_key…

2) Additional Sensitive Fields

Nomes de campo que você adiciona — remove o campo e qualquer valor que contenha aquela string.

Over-scrubbing: casa por substring no valor — termo curto apaga demais (pôr exp faz sumir "Unexpected error"). Use nomes específicos.

3) Advanced Data Scrubbing

Regra = Método (Remove / Mask / Hash / Replace) × Tipo (Regex dialeto Rust, Email, IP, Credit Card, Anything…) × Origem ($string, $message, $error.value, $user.geo.**, extra.**…). Safe Fields = exceções (preservar user.id com caminho completo).

Parte B — Regras avançadas

Security & Privacy → Advanced Data Scrubbing → Add Rule · 1–4 na org, 5–6 no projeto AutoChecker/AutoMed.

#MétodoTipo de dadoOrigemCobre
1Mask(?i)\b\d{3}\.?\d{3}\.?\d{3}-?\d{2}\b$stringCPF
2Mask\b\d{2}\.?\d{3}\.?\d{3}/?\d{4}-?\d{2}\b$stringCNPJ
3MaskEmail Addresses$stringE-mails
4RemoveAnything$user.geo.**Geolocalização
5RemoveAnything$message + $error.valueDocumento em mensagem de erro
6RemoveAnythingextra.**Contexto extra com ASO/exame
Dialeto regex = Rust (teste em regex101.com → Rust). Campo “event ID” acima de Source autocompleta caminhos a partir de um evento real (não é salvo). Regras valem só para eventos novos.
CNH: evitei regra de 11 dígitos (falso-positivo com IDs) → cubro pela chave cnh na Parte A. Parcial

Parte C — Session Replay (AutoChecker)

Regras de texto também alcançam o texto do replay Parcial. O painel não bloqueia o vídeo das telas (CNH/ASO) — isso é maskAllText + blockAllMedia no SDK (dev). Se jurídico exigir parada imediata, dá para desativar a feature Replay do projeto pelo painel. Parcial

Parte D — Logs estruturados (futuro)

Logs honram as regras padrão. Para regra avançada em log, escolha o dataset de Logs ao criar. Sei (conceito) Parcial (uso) — deixar pronto para quando ligarem a feature.

Parte E — Purgar o passado

  • Issues: abrir → ícone de lixeira (deleta a issue; não há delete de evento isolado).
  • Tags: Project Settings → Tags → remover valor (deletar issue não limpa a tag).
  • Replays pretéritos: eliminação (LGPD art. 16 c/c 18, IV) — confirmar procedimento com o DPO. Parcial
  • Caso extremo: deletar/recriar projeto — só com o dev (perde histórico, muda DSN).

Parte F — Validar

Gerar evento novo → abrir → link “JSON” → confirmar campo como [Filtered]/null/mascarado. Conferir replay novo. Marcar projetos concluídos.
